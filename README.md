# 弹幕靶场 · Danmu Range

> **你的评论区，就是我的靶场。**

B 站 **Toy** 平台的网页作品原型。一条条弹幕从屏幕顶端压下来，你端着枪把它们逐条打碎；
打碎的越多屏幕越干净，漏掉的越多屏幕越糊 —— 直到你被自己的评论区彻底淹没。

「弹幕」在这里是双关：既是 B 站的评论弹幕，也是字面意义上的**枪战弹幕**。
这个设计只在 B 站成立，别的平台复制不了。

---

## 玩法

| 操作 | 说明 |
| --- | --- |
| 左右拖动屏幕 | 走位（手机竖屏单手可玩） |
| 枪 | **自动开火**，不用点，专注走位与选择目标 |
| 糊屏 100% | 游戏结束 —— 你被评论区淹没了 |
| 「反弹」按钮 | 攒满能量后释放，把弹幕**原路打回** |

自动开火是刻意的：手机竖屏再塞一个开火键会毁掉手感，
"自动开火 + 手动走位"才能把注意力全部留给「打哪条、放哪条过去」这个真正的决策。

## 弹幕有「语义」——不是换个字，是换一套行为

| 弹幕 | 行为特征 |
| --- | --- |
| `哈哈哈哈哈哈` | 被打中后**分裂**成三条小「哈」四散，笑声会传染 |
| `就这？` | 高机动，**主动闪避**你的子弹，最难打 |
| `前排` | **成群结队**出现，一队 5 条，考验清场效率 |
| `？？？？` | 随机变向，轨迹**不可预测** |
| `下次一定` | 假动作，靠近后会**突然倒退**逃跑 |
| `太长不看` | 超长条弹幕，一枪打不碎，需要**连续命中** |
| `已三连` | 金色稀有，击碎后掉落能量 |
| `老粉报道` | 移动慢但血厚，顶着你的火力推进 |

## 「糊屏」——把「被淹没」做成看得见的压力

漏掉的弹幕**不会消失**，会变成半透明文字一层层**永久糊在屏幕上**：

```
糊到 30%   能看清，但已有杂讯
糊到 50%   视线开始受阻，要靠记忆判断位置
糊到 80%   几乎看不清，只能靠手感
糊到 100%  你被评论区彻底淹没 —— Game Over
```

结算页标题就是：**「你被 30 条弹幕淹没了」**，并且会告诉你**死于哪一条弹幕**：
`你死于「就这？」` —— 短、好笑、带排名，天生适合截图传播。

## 难度曲线（实测标定，不是拍脑袋）

用无头模拟跑难度参数扫描，标定出「一个会左右扫射的玩家」的存活时间：

| 配置 | 存活时间 |
| --- | --- |
| 初版 | 150 秒仍未死（太简单，反弹放了 82 次） |
| **当前配置** | **98 秒阵亡，全程只能放 5 次反弹** |

糊屏压力随时间可见地爬升：`0% → 13% → 70% → 100%`。
真人玩家预计 50~70 秒一局 —— 街机该有的长度。

## 本地运行

```bash
python3 -m http.server 8099
# 打开 http://127.0.0.1:8099
```

无需构建、无任何第三方依赖、无后端。

## 技术

- **纯静态**：原生 ES Module + Canvas 2D，零依赖、零构建步骤
- **适配 Toy 子路径**：全部相对路径。Toy 页面跑在 `https://www.bilibili.com/toy/<slug>/` 下，
  根绝对路径（`/js/x.js`）会解析到站点根，直接白屏 —— 这是官方明确的高频坑
- **包体约 51 KB**（4 个源文件），远低于内测 50 MB 配额
- **官方内容预检通过**：`toy_doctor.py` → `OK: Toy static checks passed`
